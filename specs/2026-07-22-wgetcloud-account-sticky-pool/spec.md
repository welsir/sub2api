# WgetCloud 账号粘性稳定池规格

## 交付归属

- 仓库：`sub2api`
- 产品线：公司业务
- 当前分支：`dev/company-01-runtime-merge`
- 首个部署目标：39 服务器

本需求不进入 `main`、`dev/omni` 或 `dev/team`。

## 目标

把 WgetCloud 订阅中的 29 个真实节点作为候选池持续检测，从中维护最多 5 个稳定生产通道，并将当前可调度的 OpenAI OAuth 账号稳定分配到不同通道，避免所有账号和服务器追逐同一个最低延迟节点。

## 核心规则

1. 29 个真实节点全部进入候选轮转；套餐日期、重置日期、订阅获取时间等 3 个元数据伪节点必须排除。
2. 生产稳定池最多包含 5 个节点，不允许 29 个未经完整验证的节点直接承载线上请求。
3. 使用一致性哈希按 OAuth 账号分配通道；账号列表必须从 Sub2API 当前状态动态获取，不得固定账号 ID。
4. 同一账号在稳定池不变时保持同一出口，不允许每个请求轮询换 IP。
5. 所有真实健康探测统一使用 `gpt-5.4-mini`，发送最小 `hi` 流式请求，并要求 HTTP 200 与有效 SSE。
6. 节点连续成功 3 次后才可进入稳定池；生产节点连续失败 2 次后摘除。
7. 生产切换验证失败时立即回滚并隔离该候选 30 分钟。
8. 常规优化最多每 30 分钟替换一个健康节点，且新节点延迟 EWMA 至少改善 30%；故障替换不受该冷却限制。
9. 账号代理绑定通过 Sub2API 服务层事务完成，不允许控制器直接写账号表。
10. 39、117、43 后续部署时使用不同服务器盐值，避免不同服务器形成相同分布；本次只实现和验收 39。

## Sub2API 所有权边界

Sub2API 负责：

- 发现当前有效的 OpenAI OAuth 账号；
- 维护节点健康、稳定池和通道状态；
- 计算账号到通道的一致性哈希；
- 通过服务层更新账号 `proxy_id`；
- 提供管理员查看、固定和解除固定通道的控制面；
- 记录不含秘密的健康与迁移审计事件。

Mihomo 负责：

- 加载 WgetCloud provider；
- 暴露最多 5 个内部 HTTP listener；
- 每个 listener 固定走对应的 lane selector；
- 通过内部 controller API 接受 selector 调整。

## 候选健康状态

每个节点至少记录：

- 连续成功和失败次数；
- 最近成功率；
- 延迟 EWMA；
- 最近结果分类和探测时间；
- 隔离截止时间。

账号范围错误（OAuth 过期、JSON 401/403、账号级 429、额度问题）只轮换探测账号，不处罚节点。WAF HTML 403、TLS/连接失败、超时、无效 SSE 或上游传输失败计为节点失败。

## 探测节奏

每 2 分钟：

- 检查所有实际承载账号的 lane；
- 检查 1 个尚未承载生产流量的候选节点；
- 重新计算健康状态和必要的迁移计划。

29 个候选约 58 分钟完成一轮后台刷新。探测凭据只存在请求进程内，不得写入日志、状态、命令行或错误正文。

## 账号粘性

使用 SHA-256 rendezvous hashing：

`server_salt + account_id + lane_id`

稳定池不变时映射必须完全稳定。移除一个 lane 时，只允许重新分配原本位于该 lane 的账号；增加 lane 时只移动被新 lane 赢得的最小账号集合。

## 事务要求

### Lane 切换

1. 记录旧节点；
2. 选择新节点；
3. 通过该 lane 执行 `gpt-5.4-mini` 完整 canary；
4. 成功才提交 lane 状态；
5. 失败恢复旧节点并隔离候选。

### 账号迁移

1. 记录账号当前 `proxy_id`；
2. 通过 Sub2API 服务层更新到目标 lane proxy；
3. 重新读取账号并执行完整 canary；
4. 任一步失败立即恢复原 `proxy_id`；
5. 单账号通过后才处理下一个账号。

## 手动控制

管理员可以查看 5 个 lane 当前节点，并对指定 lane 设置带过期时间的 pin。被固定的 lane 仍接受健康检测，确认故障时允许自动撤离；正常优化不得覆盖未过期 pin。

## 灰度与回滚

1. 保持当前代理 ID 5 与 `新加坡 03` 单跳在线。
2. 先安装 lane/listener 与代理记录，不修改账号绑定。
3. 影子环境完成至少一轮 29 节点检测。
4. 动态选择一个当前有效账号灰度 10 分钟。
5. 其余账号逐个迁移并逐个验证。
6. 新稳定池启用后停用旧的双跳自动晋升任务。

回滚时停止稳定池调度，把已迁移账号恢复到记录的原代理 ID，并保持代理 ID 5 固定 `新加坡 03`。

## 验收标准

- 当前 29 个真实节点全部进入候选轮转，0 个元数据节点进入。
- 最多 5 个 lane 可分别选择不同节点并独立完成真实请求。
- 探测模型为 `gpt-5.4-mini`。
- 没有任何固定账号 ID。
- 输入不变的 3 个调度周期产生 0 次账号迁移。
- lane 故障只迁移受影响账号。
- Sub2API 健康且无重启，线上没有新增 WAF 403、TLS、EOF、超时或 5xx 回归。
- 原代理 ID 5 与 `新加坡 03` 回滚路径始终可用。

## 非目标

- 不恢复 IPReed 双跳。
- 不做每请求 round-robin。
- 不在本次同步到 117 或 43。
- 不修改 `main`、`dev/omni`、`dev/team`。
